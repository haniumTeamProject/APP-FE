# 온보딩 + 권한 설계

작성일: 2026-08-15

## 목적

첫 실행에서 앱을 음성으로 소개하고, 조작법(제스처)을 연습으로 익히게 하고,
필요한 권한을 한 흐름으로 받아둔다. 지금은 목적지 화면에 처음 들어갈 때 마이크 권한
팝업이 그때 튀어 사용자를 당황시키는데, 이를 앞단의 안내된 흐름으로 옮긴다.

시각장애인이 화면을 보지 않고 쓰는 앱이므로, 온보딩은 "슬라이드를 보여주는" 것이 아니라
**음성으로 읽어주고, 조작법은 실제로 해보며 익히는** 것이 본체다.

## 결정 사항 (브레인스토밍 확정)

1. **권한 범위:** 마이크·블루투스·알림 세 개를 온보딩에서 모두 요청한다. (블루투스·알림은
   1차에서 실제로 쓰지 않지만, 2차 ScanService가 붙을 때 안내 도중 팝업이 튀지 않도록 미리 받아둔다.)
2. **건너뛰기:** 첫 실행 1회 자동 표시. 소개·연습은 건너뛸 수 있고, 건너뛰면 곧장 권한 단계로
   점프한다. 권한은 앱 동작에 필수라 유일한 관문으로 못 건너뛴다. 재열람은 홈에서 사용법만.
3. **사용법 연습:** 핵심 제스처(두 번 두드리기) 하나만 연습시킨다. 성공하면 진동 + "좋아요" 후
   진행. 5초간 못 하면 "괜찮아요, 넘어갈게요"로 자동 통과시켜 절대 막히지 않게 한다.
4. **권한 거부 처리:** 온보딩은 마이크·블루투스·알림을 요청만 하고, 결과와 무관하게 항상 다음
   단계로 진행한다. 마이크 거부를 온보딩에서 특별히 다루지 않는다(재안내·재요청·설정 열기 없음) —
   거부된 마이크는 목적지 화면의 목록 선택 대체가 이미 처리하므로, 그 지점에서 다루는 편이 더
   단순하다. 블루투스·알림 거부도 조용히 다음으로 진행한다.
5. **조작 모델:** 소개·완료 단계는 자동 진행하지 않고 사용자 조작을 기다린다(속도를 사용자가 통제).

## 아키텍처

온보딩은 안내 상태 머신(SELECTING_PLACE → READY → LISTENING → ROUTING → NAVIGATING → ARRIVED)
**바깥의 첫 실행 관문**이다. 상태 enum에 넣지 않는다.

- `MainActivity.onCreate`에서 SharedPreferences 플래그 `onboarding_done`을 확인한다.
  - 없으면 `OnboardingFragment`를 띄운다.
  - 있으면 기존대로 `PlaceFragment`(SELECTING_PLACE)로 시작한다.
- 온보딩 완료 시 플래그를 저장하고 SELECTING_PLACE로 전이한다.
- 단일 Activity · Fragment 구조를 그대로 유지한다.
- 4단계는 `OnboardingFragment` 하나가 내부 step 인덱스로 관리한다(별도 Fragment 4개를 만들지 않는다).
  TTS·접근성 포커스 통제를 한 곳에 모으기 위함.

프리퍼런스 접근은 작은 헬퍼(`OnboardingPrefs` 또는 동등물)로 감싸 `onboarding_done`
읽기/쓰기를 한 지점에 둔다.

## 4단계 흐름

각 단계는 진입 시 큰 글씨 + 자동 음성 안내. 디자인 톤은 앱과 동일(하늘색 히어로 #C5EBFF,
민트 액션 #8CFFB6, 제목 Ria Sans, 본문 Gothic A1).

| 단계 | 음성 안내(요지) | 조작 | 나가기 |
|---|---|---|---|
| ① 소개 | "길을 안내할게요. 목적지를 말하면 소리로 안내해요. 다음으로 넘어가려면 화면을 두 번 두드리세요." | 두 번 두드리기 → ② | 건너뛰기 → ③ |
| ② 사용법 연습 | "말하기는 화면을 두 번 두드리면 돼요. 지금 한번 해보세요." | 두 번 두드리면 진동 + "좋아요" 후 ③. 5초 미조작 시 자동 통과 | 건너뛰기 → ③ |
| ③ 권한 | "안내에 마이크·블루투스·알림을 사용해요. 허용해 주세요." → 순차 OS 팝업 | 시스템 팝업 응답(허용/거부 무관하게 진행) → ④ | 못 건너뜀(필수 관문) |
| ④ 완료 | "준비됐어요. 이제 어디로 갈지 정해요." | 두 번 두드리기 → 앱 진입(SELECTING_PLACE) | — |

### 조작 모델

- 화면 전체에 포커스 가능한 "다음" 영역 하나를 둔다.
- TalkBack 켜짐: 그 영역을 포커스해 두 번 탭(TalkBack의 두 번 탭 활성화).
- TalkBack 꺼짐: 화면 아무 데나 두 번 탭. 앱의 기존 "두 번 두드리기" 모델과 일치.
- 화면 전환 후 접근성 포커스는 기존 `MainActivity.moveAccessibilityFocus`로 첫 요소에 건다.

## 권한 로직 (③단계)

- 요청 순서: 마이크(RECORD_AUDIO) → 블루투스(BLUETOOTH_SCAN) → 알림(POST_NOTIFICATIONS), 하나씩 순차.
- SDK 분기:
  - BLUETOOTH_SCAN 런타임 권한은 API 31+에서만 실제 팝업. 그 아래는 매니페스트의
    `ACCESS_FINE_LOCATION`(maxSdkVersion 30)으로 대체되며 별도 팝업 없이 건너뛴다.
  - POST_NOTIFICATIONS 런타임 권한은 API 33+에서만 팝업. 그 아래는 자동 허용 간주, 건너뛴다.
  - RECORD_AUDIO는 전 버전 공통.
- 거부 처리: 마이크·블루투스·알림 모두 거부되어도 온보딩은 특별히 다루지 않고 조용히
  ④로 진행한다. 마이크 거부는 목적지 화면의 목록 선택 대체가 처리한다.
- 구현은 `RequestMultiplePermissions` 또는 순차 `RequestPermission` 런처. 순차 안내 음성과
  맞물려야 하므로 하나씩 요청하는 편이 흐름 통제가 쉽다.

## 사용법 재열람 (홈)

온보딩은 1회성이라, ②단계 내용을 홈에서 다시 들을 수 있는 진입점을 둔다.

- 홈(READY, `HomeFragment`)에서 **길게 누르기** → "말하려면 화면을 두 번 두드리세요" 음성 재생.
- 재열람은 설명만 한다(연습 판정 없음). 온보딩의 연습 로직을 재사용하지 않는다.
- 접근성: 길게 누르기는 TalkBack에서 발견이 어려우므로, 홈에 이 동작을 알리는 접근성 액션
  (`ACTION_LONG_CLICK` 라벨 또는 커스텀 접근성 액션 "사용법 듣기")을 함께 건다.

## 범위 밖 (이번에 만들지 않음)

- 스플래시 — 별도 항목, 나중에. (Android 12+ 기본 스플래시 API로 가볍게 얻을 수 있음)
- 로그인 / 회원가입 — 1차 미채택. 길찾기 유틸리티라 계정이 저장할 데이터가 없고, 시각장애인에게
  가입 절차는 접근성 부담이 크다. 필요해지면 그때.
- 설정 — 안내 음성 속도 등은 시스템/ TalkBack이 전역 관리. 넣을 항목이 생길 때.

## Figma

기존 와이어프레임 파일(`my-hanium-app`) 하단에 새 행 **"E. 첫 실행 온보딩"**을 추가했다
(기존 프레임은 건드리지 않음). 구조가 가장 가까운 기존 프레임을 복제해 문구만 교체 —
디자인 시스템 충실도 유지:

- **E1 온보딩 · 소개** ← 15 스플래시 복제
- **E2 온보딩 · 사용법 연습** ← 03 목적지 LISTENING 복제 (연습 카드를 민트로 강조)
- **E3 온보딩 · 권한** ← 01 온보딩·권한 복제
- **E4 온보딩 · 완료** ← 14 도착 복제 (완료에 안 맞는 하단 타일 제거)

권한 거부(18)·사용법 재열람(22)은 기존 프레임을 그대로 참조한다.

주의: 헤드라인의 Ria Sans 폰트가 Figma 자동화(MCP) 환경에 설치돼 있지 않아, 새 프레임의
헤드라인은 Gothic A1 SemiBold로 대체해 문구를 넣었다. 앱 구현에서는 기존대로 Ria Sans를
쓴다(res/font 번들). Figma 헤드라인을 Ria Sans로 되돌리려면 로컬에서 해당 레이어의 폰트만
바꾸면 된다.

## 미해결 / 후속

- 온보딩 텍스트·음성 문구 최종안은 구현 시 문자열 리소스로 확정.
- 프로세스 강제 종료 중 온보딩 진행 상태 복원은 다루지 않는다(1회성 흐름이라 재시작 시 처음부터).
